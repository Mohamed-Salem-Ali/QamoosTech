## Definition

A software development process where you write a failing automated test before writing the actual implementation code, following a red-green-refactor cycle.

## Where you hear it

In team planning sessions, coding pair programming routines, and agile retrospectives.

## Examples

- We practice TDD to ensure every new feature has automated test coverage from day one.
- Writing the test first in TDD helps clarify the requirements before we touch the implementation code.

## Common mistake

Thinking TDD is purely a testing technique when it is actually primarily a design technique.

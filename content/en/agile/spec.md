## Definition

A written description of how a feature or system should work, including its behaviour, inputs, outputs, and edge cases.

## Where you hear it

In engineering tickets, design reviews, and requests such as "Can you write a spec for this?"

## Examples

- The spec defines what happens when the payment times out.
- I wrote a short spec before we started coding.
- The spec lists the retry count, the timeout and the message the user sees.

## Common mistake

Writing a spec so long that nobody reads it. Keep it short, and cover the decisions and the risks.

## Don't confuse with

A requirement says what is needed. A spec explains how the feature will work.

## Definition

Two developers work on the same task at one computer or on a shared screen. One types while the other reviews each step, and they swap roles often.

## Where you hear it

In team channels and onboarding sessions, and in interviews that ask you to code together.

## Examples

- Let us do pair programming on the login bug this afternoon.
- Pair programming slows the first draft, but it reduces the review time.
- We paired on the database migration, and the second person caught a missing index.

## Common mistake

Letting one person type while the other watches on their phone. Both people should think about the code.

## Don't confuse with

Code review happens after the work, by someone who was not there. Pair programming happens during the work.

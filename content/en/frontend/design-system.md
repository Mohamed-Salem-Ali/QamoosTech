## Definition

A design system is a shared set of reusable components, design tokens (colours, spacing, type) and usage rules that keeps a product's interface consistent across pages and teams.

## Where you hear it

In frontend and design team meetings, component libraries (Storybook), and when a product grows beyond a few screens.

## Examples

- Use the design system's button instead of styling a new one.
- Change a colour token once and every screen updates.
- The new order page is built from the design system's card and table components.

## Common mistake

Building one with no owner. Without someone maintaining it, teams copy and drift away from it.

## Don't confuse with

A style guide, which is documentation only. A design system includes the actual reusable code.

## Say it at work

- Is that in our design system?
- Add the new variant to the system first.
